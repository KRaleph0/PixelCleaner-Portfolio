# Pixel Cleaners — 기술 문서

클라이언트(Unity)의 구조와 핵심 시스템, 구현하면서 내린 설계 판단을 정리한 문서입니다.
서버는 [`../server/README.md`](../server/README.md), API 연동은 [`CLIENT_MANUAL.md`](CLIENT_MANUAL.md)를 참고하세요.

---

## 1. 개요

GPS 핫스팟에 들어가면 지도에 오염 생명체가 나타나고, 탭하면 AR 씬에서 포획 미니게임을 합니다.
포획한 생명체를 공장 시설에 배치해 자원을 생산·합성하고, 제작한 납품 물품을 제출해 글로벌 랭킹을 겨룹니다.

| 항목 | 내용 |
|------|------|
| 엔진 | Unity 6 (6000.3.11f1), C#, Universal RP 17.3 |
| AR | AR Foundation 6.3.3 + ARCore XR Plugin 6.3.3 |
| 입력 | Input System 1.19 (신형 전용 모드) |
| 플랫폼 | Android 7.0+ (minSdk 24), IL2CPP, ARM64 |
| 위치·지도 | Unity Location Service + 래스터 슬리피맵 타일 (CARTO / OpenStreetMap) |
| 서버 | FastAPI 랭킹 서버 (`server/`) |

## 2. 씬 구성

```
LoginScene     닉네임 입력 → 서버 등록 (앱 진입점)
MapScene       GPS 지도, 생명체 마커
ARScene        AR 포획 미니게임
FactoryScene   시설 생산·제작·수거
DeliveryScene  납품 + 글로벌 랭킹
CreatureScene  생명체 도감
BagScene       포획 도구·각성제
```

- 씬은 에디터 메뉴 `PixelCleaners → 씬 생성`으로 코드에서 조립하고 Build Settings까지 등록합니다.
  UI도 대부분 씬 설정 스크립트(`*SceneSetup`)가 런타임에 UGUI로 직접 만듭니다.
- 이미 등록된 플레이어는 로그인 씬에서 UI를 만들지 않고 곧바로 지도로 넘어갑니다.
- 서버가 응답하지 않으면 "서버 없이 시작"으로 임시 ID를 발급해 진행하고, 이후 납품 제출이 404를 받으면 정식 등록합니다.

### 영속 오브젝트

```
[DontDestroyOnLoad]
├── GameBootstrap       RuntimeInitializeOnLoad — 어느 씬에서 시작해도 매니저 생성
├── SceneController     씬 전환 (+ 미등록 씬은 오버레이로 폴백)
├── LocationManager     GPS 1초 폴링, OnLocationUpdated
├── HotspotDetector     오염 등급 판별, OnHotspotGradeChanged
├── FactoryManager      공장 재고 / 창고 / 생명체 / 포획 도구 / 각성제 / 납품 점수
├── SynthesisManager    제작소 4기 (순수 C# 객체)
├── SaveManager         JSON 저장·복원 + 오프라인 시뮬레이션
└── FacilitySlots       시설 5종 × 5슬롯, 슬롯마다 HumanCycle 상태 머신
```

## 3. 포획

```
MapScene   마커 탭 → PendingCapture.Set(...) → ARScene
ARScene    카메라 권한 → ARSession 활성화 → 대상 생명체 스폰
           하단에서 포획 도구 선택 → 생명체 탭 → CaptureMiniGame
           세로 트랙의 세이프존 안에 생명체를 유지하면 게이지 상승 (터치 드래그 / 중력센서)
성공       정화(인벤토리 보관) 또는 제거(각성제 획득)
실패       티어별 확률로 도주 — 도주 시 지도 스폰 삭제
```

### 지도 스폰 — 위치·시간 기반 고정 스폰

세계를 위경도 격자(약 89m × 71m)로 나누고, 칸마다 고정된 스폰 지점을 둡니다.

- 각 지점은 1시간 주기 중 칸마다 다른 시각에 나타나 30분 유지됩니다.
- 출현 여부·종·등급·칸 안의 위치를 **칸 좌표 + 주기 번호의 해시**로 결정합니다.
  - 지도를 나갔다 오거나 앱을 다시 켜도 같은 자리에 같은 생명체가 있습니다.
  - 모든 플레이어에게 같은 스폰이 보이며, 서버가 필요 없습니다.
  - 기기와 무관한 결과를 위해 `UnityEngine.Random`, `string.GetHashCode` 대신 SplitMix64를 씁니다.
- 출현 확률은 오염 등급을 따릅니다 (Normal 35% / Polluted 60% / Hotspot 90%).
- 잡거나 도주한 스폰만 저장해 그 스폰이 끝날 때까지 본인에게서 숨깁니다.

Python으로 포팅해 24시간을 시뮬레이션한 결과, 반경 220m 안 스폰 수는 일반 지역 평균 4.8, 핫스팟 평균 10.7이었습니다.

### 난이도

| 희귀도 | 세이프존 | 속도 | 제한시간 |
|--------|---------|------|---------|
| Common | 40% | 0.20 | 15s |
| Rare | 30% | 0.32 | 12s |
| Epic | 20% | 0.48 | 10s |
| Legendary | 12% | 0.65 | 8s |
| Pixel | 8% | 0.70 | 10s (불규칙 이동) |

포획 도구는 세이프존에 보너스를 줍니다: 기본(없음, 무제한) / 강화 +10% / 정밀 +25% / 픽셀 +40%. 기본 외 도구는 제작소에서 만듭니다.

## 4. 자원 시스템

```
① 생산     시설 슬롯 + 생명체 → 사이클마다 1차 자원 → 공장 재고 → [수거] → 창고
② 제작     제작소 + 레시피 + 생명체 → 창고 재료 소모 → 2차 자원 / 포획 도구 / 납품 물품
③ 납품     납품 물품 → 포인트(일반 100pt, 고급 250pt) → 서버에 누적 총점 제출
```

### 시설

| 시설 | 요구 능력치 | 기본 사이클 | 출력 |
|------|-----------|-----------|------|
| 오염 집합소 | 오염 감지 | 10s | 쓰레기 |
| 용해 정제소 | 용해 | 15s | 플라스틱 / 유리 |
| 단조 정제소 | 단조 | 15s | 금속 / 캔 |
| 압축 정제소 | 압축 | 15s | 종이 / 섬유 |
| 픽셀 재구성소 | 특수 (제로픽셀 전용) | 20s | 픽셀 파편 |
| 일반 제작소 ×2 | 재구성 | 레시피별 | 재생 복합재, 재생 합금 |
| 고급 제작소 ×2 | 합성 | 레시피별 | 포획 도구, 납품 물품 |

제작소는 재료를 들여 Lv1~5로 확장하며, 레벨만큼 생명체를 배치합니다.
여러 마리는 처리량을 더하는 방식으로 계산합니다: `합산 사이클 = 1 / Σ(1 / 개별 사이클)`.

### 생산 속도

```
시설   : cycle = baseCycle   × max(0.90^statPower, 0.05)
제작소 : cycle = recipeCycle × max(0.90^statPower, 0.10)
```

- `statPower` = 희귀도 기본값 + 등급 보너스 + 2티어 보너스(+2), 범위 1~21.
- 요구 능력치가 맞을 때만 적용하고, 맞지 않으면 기본 사이클로 돌아갑니다.
- 능력치 1당 사이클이 10%씩 곱으로 줄어드는 지수 감소라, 같은 +2라도 구간과 무관하게 생산량이 약 23% 늘어납니다.

### 활동 사이클과 각성제

`HumanCycle`은 `Idle → Working(24h) → Sleeping`으로 움직입니다. 24시간을 채운 슬롯은 잠들고, 슬롯을 탭해 각성제를 쓰면 다시 24시간 일합니다.
제작소는 실제로 제작한 시간만 셉니다. 재료가 없어 대기하는 시간은 활동 시간에서 빠집니다.

## 5. 생명체

생명체 13종의 정의는 `CreatureRoster.cs` 한 곳에 모았습니다. AR 스폰, 지도 스폰, 도감이 모두 이 목록을 씁니다.

| 능력치 | 1티어 | 2티어 |
|--------|------|------|
| 오염 감지 | 빈코어 | 웨이스트픽스 |
| 용해 | 플라스복스 | 글라스노드 |
| 단조 | 리프바이트 | 캔버그 |
| 압축 | 스레드복스 | 페이퍼빗 |
| 재구성 (일반 제작소) | 그린빗 | 에코픽스 |
| 합성 (고급 제작소) | 클린로그 | 에코바이트 |
| 특수 (픽셀 재구성소) | 제로픽셀 | — |

외형은 재활용품 컨셉(쓰레기통·페트병·캔·플로피 디스크 등)에 맞췄고, 모델은 Meshy AI로 만든 정적 메시(종당 약 1만 삼각형)입니다.

### 에셋 파이프라인 (에디터 도구)

| 메뉴 | 역할 |
|------|------|
| 생명체 머티리얼 설정 | FBX 내장 텍스처를 종별 URP 머티리얼로 명시 교체 |
| 생명체 아이콘 촬영 | 13종 정면샷을 투명 배경 PNG로 렌더링 (도감·공장 UI용) |
| 모델 폴리곤 줄이기 | 원본 UV를 유지한 채 AR용 / 지도용 두 버전 생성 |

- **머티리얼**: Meshy FBX는 13종 모두 내장 텍스처 이름이 같아, Unity 기본 동작(이름으로 찾기)으로는 회색이 되거나 다른 종의 텍스처를 가져갔습니다. 종별 머티리얼을 만들어 명시적으로 교체합니다.
- **크기**: 모델마다 원점과 크기가 달라 `CreatureModelFitter`가 렌더러 경계를 측정해 AR 0.7m, 지도 0.1유닛으로 맞춥니다. 원본 루트 회전은 보존합니다 (Blender를 거친 FBX는 루트의 -90° 회전으로 서 있습니다).
- **폴리곤 감소**: 원본의 5% 미만으로 줄이면 AI 모델 특유의 잘게 나뉜 UV 때문에 면이 접혔습니다. 도구가 결과의 접힌 면 수를 검사해 경고하고, 그 이하로 줄일 때는 리메시를 쓰도록 했습니다.

## 6. 영속성

`SaveManager`가 `persistentDataPath/save.json`에 저장합니다.

- 저장 시점: 앱 일시정지, 종료
- 대상: 재고·창고·포획 도구·각성제·납품 점수·생명체·시설 슬롯 상태·제작소 상태·도감·잡은 스폰
- **오프라인 시뮬레이션**: 저장 시각부터 최대 72시간을 계산해 그동안의 생산·제작 결과를 반영합니다. 남은 활동 시간 안에서만 진행하고, 재료가 떨어지면 멈춥니다.
- 생명체의 능력치·티어는 불러올 때 로스터 값으로 복원합니다. 밸런스를 바꾸면 기존 세이브에도 반영됩니다.

## 7. 지도

```
GPS (lat, lon) → Web Mercator 타일 좌표 (zoom 18)
→ 5×5 타일 다운로드 (UnityWebRequestTexture) → 바닥 Quad에 텍스처
```

- 중심 타일이 바뀔 때만 다시 구성하고, 범위를 벗어난 타일은 정리합니다. 진행 중인 로드는 세대 번호로 취소합니다.
- 타일 제공자를 교체할 수 있습니다. CARTO는 API 키가 필요해, 키가 없으면 OpenStreetMap으로 자동 전환합니다.
- 카메라는 50° 기울인 정사영이고, 생명체 마커는 카메라를 향해 회전합니다.

## 9. 해결한 문제

| 증상 | 원인 | 해결 |
|------|------|------|
| AR 화면이 검게 나옴 | 카메라 권한을 받기 전에 ARCore가 카메라를 선점 | 권한 획득 전까지 `ARSession`을 비활성화하고, 획득 후 활성화 |
| 앱 실행 즉시 크래시 | Unity 6의 `GameActivity` + AppCompat 테마 충돌 | `UnityPlayerActivity` 사용 + `.androidlib`로 테마 오버라이드 |
| APK에서 지도 타일이 분홍색 | 빌드에서 `Shader.Find()`가 null | 셰이더 폴백 체인 + Always Included 등록 메뉴 |
| 신규 설치 시 앱이 시작되지 않음 | 빌드에 없는 로그인 씬을 직접 로드 | 씬 등록 여부를 확인한 뒤 로드, 빌더에 로그인 씬 추가 |
| 공장 씬을 나가면 예외 | `-= _ => Refresh()`는 새 람다라 구독이 해제되지 않음 | 델리게이트 인스턴스를 보관해 해제 |
| 지도 타일에 워터마크 | CARTO가 래스터 타일에 키를 요구하도록 정책 변경 | 제공자 교체 구조 + 키 없으면 OSM 폴백 |
| 랭킹 동점자 처리 오류 | 목록과 내 순위 API의 순위 계산이 서로 다름 | 서버에서 경쟁 순위로 통일 + 정렬 타이브레이커 |

## 10. 빌드

1. Unity 6000.3.11f1로 `client/`를 엽니다. UI 에셋 팩 임포트가 필요합니다 (루트 README 참고).
2. `PixelCleaners → Android 빌드 설정 적용`, `씬 생성`, `쉐이더 빌드 포함 설정`을 실행합니다.
3. Project Settings → XR Plug-in Management → Android → ARCore를 켭니다.
4. `ServerConfig.example.json`을 `Assets/Resources/ServerConfig.json`으로 복사해 서버 주소를 넣습니다.
5. `PixelCleaners → 테스트 APK 빌드`로 `Builds/Android/`에 APK를 만듭니다.

에디터에서는 GPS Mock(서울시청 좌표)으로 지도와 스폰을 확인할 수 있습니다.
